# Evaluation corpus baseline

This baseline attempted 34 repositories and inspected source in 33. PostHog has an incomplete-checkout failure and is excluded from the inspected count. Sixteen function targets in four repositories have JS measurements at three sizes. 5 targets pass the synthetic compute-intensity screen. **Zero demonstrated compute-dense, discovery-accepted server functions and zero measured endpoint CPU wins emerged.** Three small accepted Umami controls compile and pass parity, but lose on boundary-inclusive elapsed time.

That result is narrower than proving that real apps lack suitable functions. This is a broad source triage with a deeper measurement pass on four repositories. Many scans time out, fail to parse, or lack dependency resolution. It is not a completed, dependency-installed evaluation of every app. The retained corpus and frozen protocol support that next step. Do not publish a 0% real-app coverage claim from this baseline.

Rybbit exact beta probabilities sum repeated Lanczos log-gamma calculations over conversion counts. The scalar-sized posterior boundary gives high intensity. Approximate K-means uses the source iteration cap of 100 and 10–1,000 categories. Compact inputs contain valid sufficient-statistic triples in Float64Arrays.
