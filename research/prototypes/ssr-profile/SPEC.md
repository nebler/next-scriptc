# Controlled SSR fixture, version 1

Use `shared/data.js` as the executable data specification and `shared/concat.js` as the canonical HTML specification. Each request calls `records()` afresh. Do not cache the result or the rendered document. No I/O, clock, randomness, locale formatting, CSS, images, client interactions, or external requests belong in this fixture.

The canonical subtree is `<main id="benchmark">…</main>`, UTF-8, without whitespace between tags. It contains a header with one heading and two navigation links, a sidebar with 50 links, a section with a heading, fixed marketing paragraph, and a table, followed by a fixed footer. The table has six column headings and 500 body rows, indexed 1 through 500. Each row has ID, name, email, decimal amount string, date string, and a status badge. Each name sits in a `strong` element; each badge sits in a `span` whose class is `paid` or `pending`.

Names contain all five characters `&<>"'`. Link hrefs contain an ampersand. Escape these as `&amp;`, `&lt;`, `&gt;`, `&quot;`, and `&#x27;` in both text and attributes. Dates and amounts use the exact string algorithms in `data.js`. Preserve element order and attribute spelling. React uses separate `Cell`, `Row`, and `Badge` components. Other frameworks should retain those boundaries rather than flatten the source manually.

Framework document wrappers, asset scripts, hydration markers, and Flight scripts sit outside the canonical subtree and count toward framework request CPU and bytes. Report these differences separately. A framework that inserts markers inside the subtree must record the original bytes and describe every normalization; do not silently remove differences. The plain React and concatenation renderers must match without normalization.

Serve a fresh document on every GET. Next uses `dynamic='force-dynamic'`, `revalidate=0`; React Router uses framework SSR. Test production builds with Node 24.22.0 and identity content encoding over loopback HTTP/1.1 keepalive. Measure complete response consumption at concurrency 1 and 16. Warm up for two seconds per concurrency, then run three three-second blocks, retaining every response and latency. Capture an additional eight-second profile at concurrency 16 after two seconds of warmup. Profile captures are separate from throughput runs. Run targets sequentially. Record status counts and errors; do not discard failed samples.
