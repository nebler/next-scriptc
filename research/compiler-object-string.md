# C1: object and string runtime costs

2026-11-02. One local compiler fix is committed: `next-scriptc/object-key-array-construction`, `0f66b43c5ba7fc11e6d2d930c25566f03bca6527`, based on freshly fetched upstream `38cc546e0`. Dense native key snapshots improve 11–15% in four alternating windows. The complete erased JSON walk improves 1.7% in the final session; large CSV does not improve. The roughly 6× CSV deficit is reproduced and remains unresolved. These are local elapsed-time measurements, not production CPU savings.

## What was measured

[Harness and raw evidence](compiler-object-string/) contains only our fixture code, measurements, compiler excerpts, and logs. No bundled dependency source or native binary is committed. Six own-code workloads cover event aggregation over typed records, string concatenation and splitting, Map/Set churn, record spread, generic identity helpers over records, and erased JSON object walks. Sizes are 1k, 10k, and 50k records/iterations. The event workload is a development aggregate, not held-out Papermark. CSV separately reuses L1's package/version and parse-plus-convert call shape with our own nested record fixture. It is a new executable experiment, not a repeat of L1's addon measurement or exact fixture.

Host: Apple M4 Pro, macOS arm64; Node 26.12.0. L1/L2 used Node 26.13.0. Compiler lanes are fresh registry scriptc 0.4.6, fetched upstream 0.4.7 sources, and those same sources with this runtime change. The LLVM 22.1.8 helper was copied read-only from the existing fork's built package; it was not rebuilt. The candidate worktree built its TypeScript compiler and a complete seven-flavor Darwin runtime pack from source. Only default release/dev `scr_json.o` were then replaced for the candidate using [the retained unit rebuild script](compiler-object-string/rebuild-runtime-unit.mjs), with manifest size/hash updates. Other runtime variants remain baseline. Sanitized corpus tests compile the changed runtime sources directly. A clean production build must rebuild the entire runtime pack on the patch branch.

Each process warms 50 calls, then records 35 calls timed with `performance.now()` around computation. Startup, stdout, and addon transport are outside these clocks. Fixture construction is included in the six-workload suite; CSV's input JSON and the key-only workload's objects are built before timing. The suite compares every numeric result against Node. CSV compares every full output string across all four lanes and stores byte counts and SHA-256. All final cells pass. Checksums establish these deterministic fixture outputs; they do not certify arbitrary JavaScript behavior.

Final suite sessions run sequentially after builds/tests finish. Lane order is stock, baseline, patched; each cell runs Node then native. They are separate processes, not paired calls or confidence intervals. Earlier five-warmup and build-overlapped runs remain explicitly preliminary (`baseline.json`, `baseline-warm.json`, `patched.json`). Native clocks have roughly microsecond resolution. Tiny generic timings and tiering transitions merit caution.

## Ranked attribution and evidence

Profiles use macOS `sample PID 3 1` for each suite workload and `sample PID 5 1` for CSV, while repeatedly executing 50k records or 4,096 CSV rows. Samples include warmup, formatting measurement output, and stdout to an ignored pipe. CSV profiles briefly overlapped key-fixture compilation; they are attribution evidence, not timing evidence. Raw profiles are retained, gzip-compressed where necessary. Some stacks include unknown frames. No Instruments entitlement failure occurred; `sample` worked without privilege changes.

[Attribution JSON](compiler-object-string/attribution.json) classifies the profiler's exclusive top-of-stack rows with at least five samples. These are transparent symbol-based groups, not a complete cost accounting: functions inline across categories, allocation can occur inside parser/record code, and small rows are omitted. Percentages below use all main-thread samples as denominator. Do not add inclusive subtrees to these exclusive shares.

1. **Erased value ownership and boxing.** In stock CSV, ownership/destruction names account for 17.8% of samples and allocation/boxing names for another 7.8%. Upstream gives 18.9% and 7.2%. The hottest stock symbol is `scr_dyn_release` (230/3,795), followed by disposal, layout search, and byte comparison. `scr_dyn_new_num`, `scr_dyn_new_str`, retain/release glue, closure environments, and boxed receivers recur throughout path evaluation. Small-object allocation is often inlined; these named shares undercount it. The generic fixture is more decisive: 1,425/2,288 samples (62.3%) are in the generated record-release slow path. It performs trivial arithmetic but still constructs/releases records every iteration. Native `nm` contains `sc_bf_run` and no generic helper symbol: generic specialization/call overhead is not the dominant cost in this fixture. LLVM contains specialized identity bodies plus explicit record constructors/releases. A runtime allocator replacement alone would leave that ownership work.
2. **Dynamic property/layout probing and dispatch.** Stock CSV has at least 14.4% exclusive samples in property/layout probe names (15.2% upstream), and another 5.9% in dynamic call/closure names (5.6% upstream). These omit substantial generated receiver/type checks and glue. The stock call tree places 1,884/3,795 samples below `processRecords` and 1,296 below `retrieveRecordFieldData`, through `scr_dyn_invoke_impl`; these are inclusive path costs, not invocation-overhead percentages. `findFirstNonEscapedDotIndex`, `evaluatePath`, and their generated computed/property access wrappers repeatedly box indices, probe receivers, compare keys, and retain/release intermediate values. V8 can specialize these hot shapes and scalar operations; the ahead-of-time erased path pays general runtime contracts repeatedly. Direct property lookup alone therefore does not explain the whole gap.
3. **String/byte work and number formatting.** Named stock CSV string/byte/number-text functions account for at least 9.6% exclusive samples (10.5% upstream). The dedicated string workload has 746/2,287 samples in mixed concatenation, 280 in number formatting, 290 in memmove, 229 in split-piece construction, and 216 in memchr. These costs are workload-specific, and the string workload already beats V8. Source inspection finds geometric concat capacity, unique-owner append, ASCII facts, UTF-16 indexing metadata, and cached Map string hashes already implemented. Replacing concatenation with a benchmark-specific builder or treating UTF-8 offsets as JS UTF-16 indices would be unsound.
4. **JSON tree construction/destruction and key snapshots.** The erased JSON fixture's parse subtree is 651/2,291 samples (28.4% inclusive), destruction of the result tree 368 (16.1% inclusive), and native key enumeration 323 (14.1% inclusive). Named ownership routines collectively account for 29.4% exclusive samples. Key enumeration creates a fresh array and fresh key strings, then uses `scr_arr_push_ref` even though capacity is known. This is the bounded fix below. CSV's parse subtree is much smaller than its repeated conversion/path machinery; faster JSON decode cannot recover a 6× loss by itself.
5. **Map/Set hashing, bounds checks, and cycle collection are not a universal explanation.** The event profile has 664/2,284 samples in the Map entry path, including 164 in hash folding; record/string teardown contributes another large subtree. It nevertheless runs over 2× faster than Node. Map uses cached string hashes and compact layouts already. Emitted loop/type/bounds checks share `sc_bf_run` samples and cannot be given a defensible independent percentage from this sampler. There is no evidence here that tracing/cycle collection dominates CSV; most visible lifetime cost is RC and destruction. A wider hardware-counter or instrumentation study is required to split cache misses, branch checks, and inlined allocator cost precisely.

These profiles identify concrete execution mechanisms and responsible library paths. They do not fully partition the CSV deficit, prove behavior for every library, or establish a causal gain from removing any entire category.

## Landed fix: dense owned key arrays

`scr_dyn_own_key_strs` now allocates fresh inline native string arrays, transfers owned strings directly into dense slots, then publishes `len`/`filled`. Both the typed-record and plain-object paths retain their existing presence/enumerability tests and key ordering. No getter executes during this metadata enumeration. All elements are retained or freshly owned, the array is fresh on every observable call, and growth uses existing inline-array migration. Shared internal record-key caches and proxy/fallback paths are unchanged.

The targeted key fixture enumerates four keys (including integer ordering) over 50k prebuilt erased records. Four process windows alternate baseline→patched and patched→baseline, 50 warmups and 75 samples per lane. Median milliseconds per window are 8.001→6.905, 8.018→6.927, 8.159→6.951, and 7.824→6.960: 11.0–14.8% lower. The pooled median is 8.0265→6.9325 ms (13.6% lower), descriptive only; windows are the independent units. No general end-to-end saving is inferred.

Validation on the patch:

- Worktree-local install and `pnpm -r build` pass. Frozen install first fails with `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH`; non-frozen install succeeds. Its lockfile drift is reverted and is absent from the commit. Initial commands used Node 23.10; all final benchmarks and test commands use Node 26.12.0.
- Seven-flavor native runtime build passes. Initial executable compile fails with SC3003 while that pack is still building, then succeeds once it completes. Private unit rebuild emits two existing const-qualifier warnings in `scr_json.c` at `scr_string_to_number` calls; no error.
- `SCRIPTC_TEST_WORKERS=2 pnpm test packages/runtime/src/scr_json.test.ts`: 2 tests pass, 55.64 s. Both compile with ASan+UBSan, audit false/true, then run cycle thresholds 1/7/256. New C assertions cover ordering, empty snapshots, independent arrays, release after the object dies, and growth beyond inline capacity.
- `SCRIPTC_TEST_WORKERS=2 pnpm test tests/harness/llvm-differential.test.ts -t object-keys-owned-dense-array`: 1 corpus case passes release+dev. It covers hidden fields, getters not called, independent mutation/growth, deletion/addition, integer ordering, and typed optional fields.
- The same corpus with `SCRIPTC_SAN=1`: passes release+dev, ASan and RC audit, 57.82 s total.

- Generated single-fixture preflight/order baseline has no diagnostics and matches a separate frontend recheck. `pnpm test:ts7 --baselines-only` passes completeness. An accidentally broad order-canary command is terminated before a verdict; no canary sweep pass is claimed.

## Designs for the larger costs

**Escape analysis and scalar replacement.** Start with acyclic record literals whose identity never escapes a function. Build def-use/effect summaries through specialized generic helpers; allow field reads and identity-preserving local aliases. Reject escapes through closure capture, return, foreign/dynamic calls, reflection, prototype/descriptor changes, weak collections, unknown stores, and observable identity comparisons. Use stack storage with lifetime markers, or direct SSA fields, only after proving destruction cannot run user code. Keep allocation timing/resource-exhaustion behavior within the compiler's existing optimization contract. Then allow the ordinary optimizer to remove constructors and RC pairs. Differential tests must include escaping aliases, mutation through aliases, exceptions/cleanup, nested owned fields, accessors, and typed-to-erased transitions. The generic fixture predicts headroom, not a measured speedup for this design.

**Guarded specialization of erased operations.** Carry exact primitive/shape facts through hot local expressions, with explicit invalidation at calls that can invoke user code. Cache a property slot only with object-kind/layout and descriptor guards; handle missing fields and prototype fallback correctly. Preserve proxies, getters, inherited properties, key coercion, symbol keys, exceptions, and single evaluation order. Prefer existing checked layout/probe machinery over a new unchecked object model. Optimize dynamic numeric induction and string indexing only with proven primitive operands; numeric strings, NaN, −0, coercion hooks, astral text, and lone surrogates must retain JS behavior. Add a minimized CSV path-processing reproducer before changing this area. This is larger than a local runtime shortcut and is not implemented.

**Key string sharing.** A later layout-owned cache could avoid copying immutable key strings for every `Object.keys` result, but the returned array must remain fresh. Define cache ownership/teardown, workers, dictionary transitions, integer ordering, and hidden properties first. A global strong cache would retain arbitrary user keys indefinitely; that is not justified. The current patch deliberately keeps existing key string ownership.

## Reproduce and remaining work

Create a compiler worktree from the recorded upstream base and another branch for the patch as needed, keeping at most one native build tree at a time. Use Node 26.12.0 on PATH, install dependencies only there, run `pnpm -r build`, provide the LLVM 22 helper, and run `pnpm --filter @scriptc/runtime-darwin-arm64 build:native`. Compile `research/compiler-object-string/workloads.ts` with `SCRIPTC_CHECKER_SERVER=0 node <compiler>/packages/cli/dist/main.js build <source> -o <binary>`. Run `node research/compiler-object-string/bench.mjs <binary> <results.json> 35`. The harness writes caller-selected outputs; use new filenames to retain this evidence.

For CSV, install pinned scriptc 0.4.6, json-2-csv 5.5.0, and esbuild 0.25.12 into a task-owned external directory (the retained toolchain lock records dependencies). Run `node research/compiler-object-string/csv-build.mjs <install> <external-bundle.mjs>`, compile the bundle with each compiler, then `node research/compiler-object-string/csv-measure.mjs <external-bundle.mjs> <stock-binary> <baseline-binary> <patched-binary> <results.json>`. For isolated key enumeration, compile `keys.ts` for baseline and patch and run `keys-measure.mjs <baseline> <patched> <results.json>`. Profile suite binaries with `profile.mjs <binary> <output-prefix>`; CSV uses the same sample command with arguments `4096 1000000`. Generated bundle, binaries, caches, dependencies, and runtime packs are disposable.

Next priorities are an escape-analysis prototype and a reduced dynamic CSV path evaluator with guarded primitive specialization. The original typed CSV support blockers remain outside this change. L2's fastest-levenshtein is not rerun, and no held-out app is executed. Stand-in CPU confirmation, randomized lane order for the full suite, a production addon CSV recheck, worker/library runtime variants, and the full validation gate remain open. No adapter or dispatch policy changes, Docker, remote issues, PRs, pushes, or public writes occur.
