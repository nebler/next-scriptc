# Hosted vector protocol, registered before hosted requests

2026-10-31. No Sandboxes and no local timing benchmarks. Build and correctness smokes only on the busy Mac. Existing demo vector kernels, corpus, query fixture, top-10 contract, heavy HTTP client, Vercel build helper and pinned Go IPC packaging are reused.

Six variants: patched natural TS with CPU dispatch; stock 0.4.6 natural TS with dispatch; stock imul with dispatch; Go plain with GOAMD64=v1 and no experiment; experimental Go archsimd with GOAMD64=v3 and GOEXPERIMENT=simd; vanilla Node natural TS. Three fresh preview sets. Node and the two Go Functions share a deployment; each native compiler gets its own preview. Native natural and imul share their compiler's Function. All Functions request iad1, x86_64, 2048 MiB, 300 s. Do not change project settings.

First request immediately after each deploy to each variant, before diagnostics/warmup. Only the first endpoint is deployment-first; other endpoints are Function-first or route-first as labelled. No claim of certified process-cold state. Then collect diagnostics. Ten C=1 warmups and 40 measured C=1 requests per variant per set, interleaved one request per variant in rotating/reversed orders. Each variant uses a keep-alive pool, maxSockets=1. One short C=4 window per variant per set: 4 warmup requests, then dispatch for at most 2 seconds or 16 requests, first limit wins, drain all. Fresh concurrency pool. Stop on HTTP or result-hash failure; retain all partial evidence. No selective timing reruns. Request budget 1800, previews at most 10 including an optional forced-baseline diagnostic. No retries of application requests.

Server compute: monotonic elapsed time after the complete body read, before query JSON parsing/validation, through corpus search, selection and JSON serialization/Response creation. Excludes corpus initialization, body transport, diagnostic/timing-header construction and response transport/framework/IPC work. Same boundary definition for TS and Go. CPU: process user+system microsecond delta around the same work, direct per-request self-report. C=1 CPU is comparable in scope to the timed work but still includes any other process work/threads; C=4 overlapping CPU is retained but not divided into a per-request efficiency claim. RSS: serving-process resident bytes immediately after work. Go excludes separate IPC proxy. Neither CPU nor RSS measures the whole platform or billed Active CPU.

Every application response validates status, JSON content type, no-store, dynamic CDN state and SHA-256 of drained bytes against a local correctness reference which agrees with the previous HTTP experiment. Retain timing, CPU, RSS, instance token and request ID for every response. Record client CPU and wall time. Pooled nearest-rank p50/p95 over all 120 C=1 samples per variant, plus each set's p50/p95. No confidence interval, fleet ranking or sustained-capacity claim. End-to-end latency is secondary and includes the WAN from this Mac to iad1.

Retain compiler/runtime/ELF hashes and byte sizes, generated entry and optimized codegen evidence, complete CPU flags from the serving native processes and the CPU-level environment override. A final forced-baseline preview may use the identical patched binary with SCRIPTC_CPU_LEVEL=baseline for 5 warmups and 10 measurements, excluded from headline rows. This is diagnostic evidence, not another headline sample to select.
