# Installed adapter and local Vercel build checks

The packed-install gate exercises the published file layout in a fresh Next app outside this repository. The local Vercel gate uses the same app and real Next adapter hooks, with a filesystem output fixture in place of Vercel's output adapter. Neither gate invokes the Vercel CLI, logs in, links a project, deploys, or calls the Vercel API.

## Failures and fixes

A packed install failed before discovery. The adapter imports the promotion runtime during config loading, and that runtime imported `json.ts` from inside `node_modules`. Node rejects type stripping there with `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`. Workspace symlinks concealed the failure because Node resolved the source outside `node_modules`.

The Node runtime now imports `json.mjs`, generated by stripping `json.ts`. The native compiler still receives the TypeScript source. A unit test checks that both files stay synchronized. To regenerate the JavaScript file after changing `json.ts`, run this command from the repository root:

```sh
node --input-type=module - <<'JS'
import {readFileSync,writeFileSync} from 'node:fs';
import {stripTypeScriptTypes} from 'node:module';
const dir='packages/next-scriptc/src/functions/';
writeFileSync(dir+'json.mjs','// Generated from json.ts with node:module stripTypeScriptTypes (mode: strip).\n'+stripTypeScriptTypes(readFileSync(dir+'json.ts','utf8')));
JS
```

The source audit covered `require`, `require.resolve`, dynamic imports, and `new URL` references under `packages/next-scriptc/src`. Two TypeScript resolutions still fell back to `examples/demo`. Those fallbacks are removed. Standalone construction and closure checks resolve TypeScript from the calling app's working directory. Discovery already passes the app's checker explicitly. The promotion builder now retains the proof produced with that checker instead of recomputing it through an implicit resolution.

The remaining bare package loads are Next's declared peer dependency, scriptc's declared dependency, or Node builtins. Relative imports and URL reads refer to files included in the tarball. No additional optional package or repository-relative fallback was found.

The Vercel branch compiled promotion directly into `distDir/scriptc-promotion`, where Next cleanup could delete it. Unlike local builds, the branch skipped publication at completion. Both branches now compile into `distDir/cache/scriptc-promotion`. The shared `publishPromotion` helper copies the three runtime artifacts before the hosted output adapter runs. Publication does not consume the native sidecar build plan. `buildVercelFunctions` then copies the runtime files into each traced Node function's `.next/scriptc-promotion` directory.

## Gate assertions

`scripts/packaged-install-check.mjs` runs serial JS, auto-promotion, and local hosted-path builds. Each Next build uses at most two workers. The script:

- Packs `packages/next-scriptc` with npm and installs that tarball in a temporary external app. It clears inherited compiler overrides, `NODE_PATH`, and hosted adapter settings, and rejects links into this checkout.
- Installs the adapter's declared dependencies plus Next, React, React DOM, TypeScript, and the app's Node and React type declarations. The fixture permits scriptc's stock install script explicitly for npm versions that require `allowScripts`.
- Discovers a synchronous JSON loop, a function importing an ESM app helper, an optional-field input, and a destructured parameter. The ESM helper uses a literal numeric constant so its untyped JavaScript parameter cannot introduce coercion into the effect proof.
- Checks construction and dependency reports, accepted IDs, the app's TypeScript path, and the final addon after Next cleanup.
- Starts both production builds and compares response bodies byte for byte. The auto build receives 70 spaced requests per function. Every function must have a verified native shadow, dispatcher shadow logs, and no unavailable or demotion log. A dedicated crash-guard directory must contain an initialized build guard.
- Runs the real hosted branch with `NEXT_SCRIPTC_VERCEL` and `NEXT_ADAPTER_PATH` pointing to a local fixture. Zig cross-compiles the promotion addon for `linux-x64-gnu`. The script checks its ELF header and x86-64 machine type, then checks all three artifacts byte for byte in the traced Node function output. Plain Node and Edge outputs must omit them.
- Reproduces the final filesystem copy into `.vercel/output/functions/**/.next/scriptc-promotion/` and verifies the addon bytes there. It removes the complete temporary app, dependencies, native builds, and tarball in `finally`.

The unit regression in `test/vercel.mjs` separately simulates cleanup and asserts that publication precedes the output adapter. It checks Node inclusion and plain Node and Edge exclusion.

These checks do not execute the Linux addon on macOS, verify Vercel's proprietary output adapter, or prove hosted deployment behavior. Native execution and HTTP parity use the host addon. The Linux check proves cross-compilation and retention through the adapter's local hosted lifecycle and filesystem output copy.

## Run the checks

Prerequisites are Node 24 or newer, npm, a host C compiler, Zig on `PATH`, and Node C headers. `NODE_HEADERS` can specify the directory containing `node_api.h`. Without that override, the builder uses its existing node-gyp cache default for Node 24.22.1. npm registry access is needed for app dependencies and the GNU x64 runtime pack. No Vercel access is needed.

```sh
NODE_HEADERS=/absolute/path/to/include/node npm run test:packaged-install
```

To retain the gate report as a CI artifact:

```sh
PACKAGED_CHECK_REPORT=/absolute/path/to/report.json npm run test:packaged-install
```

The script exits nonzero on any failed assertion. The optional report records checker identity, construction and dependency reports, dispatcher snapshots, and the Linux artifact type. A CI job can use the root npm script without installing workspace dependencies first. Capture stdout and stderr separately if full build logs are required.

Run the full adapter suite in an installed development workspace:

```sh
cd packages/next-scriptc
node --test --test-concurrency=2 test/*.mjs
```

## Validation

The final run passes all 86 adapter tests on Node 26.13.0 and both shim tests on Node 24.22.0. The packed app uses Next 16.4.3, React 19.3.0, and TypeScript 5.9.3. All four functions complete three verified native shadows each, with zero native fallbacks. All 280 HTTP response bodies match the JS-only build. The local hosted-path build retains the Zig GNU Linux x64 ELF addon in the simulated final function output. [Retained results](install-and-vercel-build-checks.json) record these assertions without timing samples. Initial development runs found the packed JSON import failure and rejected an untyped arithmetic helper under the existing coercion proof. The fixture now imports an ESM constant helper without weakening that proof. An initial suite run also encountered the previously documented checker execute-permission issue in reused dependencies. The final suite uses a fresh stock npm compiler installation. No compiler source or package files were modified.
