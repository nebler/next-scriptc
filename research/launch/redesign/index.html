Spec sheet (revised) shows the requested "use native" directive where the adapter supports it in a route: a named module-level async function with a JSON result (greet), called from an ordinary route.ts GET. The generator runs the real extractor (packages/next-scriptc/src/functions/extract.mjs) on the snippet and asserts it finds greet. Inside route.native.ts the directive would be a no-op (those files are skipped by function extraction), and a file-level directive in a route file fails the build (src/routes.mjs). On Vercel this is supported: next-scriptc vercel-build bundles a Linux sidecar into each Node Function (packages/next-scriptc/src/vercel.mjs, bundleFunctionSidecar), and calls reach it over loopback HTTP. Verified in research/use-native-vercel.md.
