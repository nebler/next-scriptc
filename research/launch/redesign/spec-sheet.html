Vector search: memory (4 runtimes)

Method, scope and sources

Spec Sheet only (new). Same hosted run, same 120 C=1 requests as the server-compute chart: median post-work serving-process RSS, native 81.137, Go SIMD 81.789, Go 81.82, Node 153.711 MiB. Every runtime holds the same 100,000×768 int8 corpus (76,800,000 bytes ≈ 73 MiB), so most of each bar is the data and native and Go are effectively tied (native is 0.7 MiB lower than Go SIMD, within instance/GC variation). Node is 1.89× native. Coverage: Go’s numbers exclude its separate IPC proxy process; native includes its in-process IPC runtime; Node includes all process threads. Process RSS only, not whole-instance, PSS or billed memory. Never compared with the hello-route 5.6/80 MiB values, which are a different workload and protocol. Source: research/vector-vercel.md#measurements.

Code: hello route

Method, scope and sources

Monolith, Editorial and Signal keep the original route.native.ts hello handler. Spec sheet (revised) shows the requested "use native" directive where the adapter supports it in a route: a named module-level async function with a JSON result (greet), called from an ordinary route.ts GET. The generator runs the real extractor (packages/next-scriptc/src/functions/extract.mjs) on the snippet and asserts it finds greet. Inside route.native.ts the directive would be a no-op (those files are skipped by function extraction), and a file-level directive in a route file fails the build (src/routes.mjs). On Vercel this is supported: next-scriptc vercel-build bundles a Linux sidecar into each Node Function (packages/next-scriptc/src/vercel.mjs, bundleFunctionSidecar), and calls reach it over loopback HTTP. Verified in research/use-native-vercel.md. An earlier note here said the directive fell back to Node on Vercel; that described an older adapter and is withdrawn. route.native.ts is a separate API that compiles the whole handler into a native Function; the Spec Sheet hero keeps that snippet.

Where Go numbers exist (and where they don’t)

  • Vector search, hosted: matched four-runtime data for server compute, process CPU and process memory (vector-vercel.md) and in-region full request time (vercel-near-client.md). Shown: compute, full-request and memory charts.
  • Hello, revenue, nearby-store CPU; hello-route memory; first response after deploy; the "use native" page: measured native vs Node.js only (vercel-final.md, use-native-vercel.md). No matched Go measurement exists for these, so those charts stay two-way. Adding Go would need a new benchmark.
  • CSV / JSON / thumbnail / bcrypt routes (go-territory.md) have Go numbers, but the hosted Go run used a separate 1-vCPU load generator from the Node/native run, and these are different workloads. Not charted. Go wins several of them (self-hosted CSV p50 86 vs 377 ms for native, bcrypt, resize).
